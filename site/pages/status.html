Asking the server…

This takes a moment.

    What each line means

    Site and API
    The server that stores vaults and answers the vault page and the connector. If it does not answer, this page says so.
    Vault database
    Where the encrypted vaults live. The status request reads from it, so an answer means it is reachable.
    Seal job
    Folds every finished hour of reads into one seal. Catching up means reads from a finished hour are not sealed yet; late or failed means the job stopped.
    Seal copies
    Whether each seal is also posted to a webhook outside this server, so a copy of the chain lives where the server cannot change it.
    Immune test
    The public hourly attack on the hidden-instruction checks. Its full record is on the immune page.
    Backups
    Automatic copies of the database on the server's disk. They hold the same ciphertext as the database.
    Waiting reads
    Reads made in the running hour. They are sealed when the hour is over, never earlier.
    The totals
    Totals only, shown once the server holds 100 vaults. Nothing in them names a person, a vault, an app or a memory.

    Ask it yourself

    The same public endpoint this page uses. No key is needed. The full answer is described in the API reference.
