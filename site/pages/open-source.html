The repository

Synovax-Dev/Synovax-Technology: one repository, plain JavaScript, no build step. The server needs nothing from npm at all.

shared/

The cryptography (AES-256-GCM envelopes, key derivation, sealed boxes, app keys), the Merkle seals, the hidden-instruction checks, and the test vectors. The same files run in the browser, in the connector and on the server.

server/

The HTTP API on Node's built-in SQLite, the hourly sealer, the public immune test, backups, the admin password and the holder count for $SYNOVAX. It only ever handles ciphertext for what you write.

web/vault/

The vault app: sign in, memories, inbox, apps, read log, settings. Plain JavaScript modules, encrypting in your browser.

connector/

The MCP server people run on their own machine, with search by words and, optionally, by meaning with a local model.

web/ (the rest)

The home page, the docs, the admin panel and these pages. The sources of these pages are in site/pages/, built by scripts/build-pages.mjs.

test/

End-to-end checks against a real server and connector, a headless browser test of every flow, and tests for the wallet, the immune system, the test vectors and search by meaning.

Your own SYNOVAX

Needs Node.js 22.13 or newer, for the built-in SQLite. It serves on http://127.0.0.1:8787. Nothing else is required: no account, no external database, no third-party service. The quickest way is the npm package, synovax, which keeps its data in .synovax in your home folder:

Terminal
npx synovax

Or from the code, which keeps its data in ./data:

Terminal
git clone https://github.com/Synovax-Dev/Synovax-Technology.git
cd Synovax-Technology
npm start
  • Your vault then lives on your own machine, and your connector points at your own address. The vault shows the connector's config for you.
  • On first start the server prints a random admin password once; change it in the admin panel, or set ADMIN_PASSWORD.
  • For a public address, put it behind HTTPS (a reverse proxy) with HOST=0.0.0.0 and TRUST_PROXY=1, and back up the data folder.

Tests

Terminal
npm test               # end to end: server, crypto and connector over MCP
npm run test:ui        # every flow in headless Chrome or Edge, desktop and phone
npm run test:immune    # every attack in every disguise, and no false alarms
npm run test:vectors   # the open standard's test vectors
npm run test:wallet    # connect wallet and the holder count
npm run test:semantic  # search by meaning (downloads the model)

Settings

VariableDefaultMeaning
PORT, HOST8787, 127.0.0.1Where the server listens.
DATA_DIR./dataThe database, secrets and backups.
SEAL_PERIOD_MS3600000How often the read log is sealed.
SEAL_PUBLISH_URLoffPost every new seal to this webhook, so a copy of the chain lives elsewhere.
IMMUNE_TESTonThe public hourly test of the hidden-instruction checks. off turns it off.
TRUST_PROXY0How many reverse proxies are in front, so rate limits see real addresses.
TLS_CERT, TLS_KEYoffServe HTTPS directly.
BACKUP_INTERVAL_MS, BACKUP_KEEP6 hours, 14Automatic database copies.
STATS_MIN_VAULTS100Totals appear on the home and status pages from this many vaults.

Every setting, including those for the $SYNOVAX section, is in the README.
