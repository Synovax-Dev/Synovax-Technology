Immune system

Attacked everyhour, in public

Mail, chats and imports can carry text written to steer an AI. Every memory is checked before a model sees it, and every hour this server attacks those checks with a fresh set of disguised attacks and publishes what happened.

The latest round

Each row is an attack, each column a disguise. A filled square means the attack was held: its instruction no longer reached the model's input. A dashed one means it got through.

Loading the record…

The same record, as data: GET /api/immune for the latest round and the hours before it, GET /api/immune/<hour> for one round by its start time in milliseconds.

Three lines of defense

Checked on the way in

When a memory is imported, suggested by an app, or opened in the editor, your vault reads it on your device. Imports leave out what looks like instructions for an AI unless you take it; suggestions and memories show a "looks like instructions for an AI" note with the reasons.

Removed and quoted on the way out

Before the connector hands any memory to a model, it drops invisible characters, replaces each flagged place with a marker, and quotes the text between delimiters carrying a code that is new for every answer, with a note that it is data, never instructions.

On the record

Every time the connector removes something, a "caught" line goes in your read log, sealed with its hour. The server gets the memory's id, never its text.

What the checks look for

The text is read after removing invisible characters and mapping look-alike Cyrillic and Greek letters to Latin ones, in lower case, so a disguise does not change what is matched. The rules go after what an owner would not write about themselves, and leave preferences alone: "answer in short bullet points" or "act as a strict code reviewer" pass untouched.

KindWhat it finds
Instruction overrideIgnoring or replacing the instructions an AI already has; "new instructions:"; keeping something from the user.
Fake system messageChat template tokens such as <|im_start|>, system or assistant tags, [SYSTEM], and a "System:" line that goes on to give orders.
Sending data awayAsking to send memories, keys, passwords or the conversation to a web or email address; image links whose address carries data out.
Tool callThe connector's tool names with a verb that calls them, tool-call markup, and tool calls written as JSON.
Payment requestAsking to send or move money or tokens to a wallet address, or to approve a token allowance.
Jailbreak phraseDeveloper mode, "do anything now", "no longer bound by your rules" and the like.
Hidden textZero-width characters, direction controls and Unicode tag characters (a joiner inside an emoji is allowed); words that mix Latin with look-alike letters; text styled out of sight.
Encoded instructionsA run of base64 that decodes to text the other rules flag.

A flagged place is removed with the paragraph around it, since half an instruction left behind can still steer; in a very long paragraph, only the sentence goes. A place inside an HTML comment is removed with the whole comment. The rules are in shared/immune.js, the one file the vault, the connector and this test all use.

How a round works, and what it does not prove

At the start of every hour the server takes each attack, dresses it in each disguise (random capitals, invisible characters, look-alike letters, an HTML comment, base64, a quoted email), and places it in a test memory between ordinary ones. Where the invisible characters go, which letters are swapped and which ordinary memories surround it change with the hour, from a seed made from the hour itself, so anyone can run a round again and get the same result.

The memory then goes through memoryForModel(), the exact function the connector uses before anything reaches a model. Each attack carries a marker. If the marker (or, for base64, the encoded instruction) is still in the text that would go to the model, the attack got through.

There is no model in this test

It measures the checks, not how a model treats quoted data. An attack that gets through here would still reach the model quoted as data, and what a model does with that is up to the model. A round shows how these attacks fared, not that no attack can get through.

Each round's hash covers its hour, its counts and every result, and the hash of the round before it, so a past round cannot be changed without breaking every later one. Rounds are kept for 90 days. To run any hour yourself, from a copy of the code:

Terminal
node --input-type=module -e "
      import { runRound } from './server/immune-round.js';
      const r = runRound(Date.UTC(2026, 10, 25, 6));
      console.log(r.held, 'of', r.total, 'held');
      "

A server can turn the test off with IMMUNE_TEST=off; this page then says so.
