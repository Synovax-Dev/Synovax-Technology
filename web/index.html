        security · how it is built

        built so wecan't read it

        Your memories are locked on your device before they leave it. The server holds noise, each app holds only what you allow, and every read leaves a sealed trace.

        key size
        256-bit
        pbkdf2 rounds

        threat model · running0 / 7 held
          • Someone steals the database: they get ciphertext only, with no keys inside.
          • The server owner looks: they cannot see titles, text, tags, folder names or what the AI searched.
          • Someone guesses passphrases: each guess costs 600,000 PBKDF2 rounds and logins are rate-limited.
          • An app key is stolen: it only opens that app's folders, and revoking it stops it on the next request.
          • The server swaps your inbox key: the vouch check fails and the suggestion is refused.
          • Someone edits the read log: the Merkle root no longer matches and the proof fails.
          • Someone injects a script: the content security policy only runs scripts from this site.
          1. 01

            encryption

            aes-256-gcm

            Every memory is encrypted in your browser with its folder's key. Change one bit of the ciphertext and it refuses to open.

          2. 02

            key derivation

            600,000×

            PBKDF2-SHA-256 rounds turn your passphrase into a key, so every single password guess costs real time.

          3. 03

            on the server

            0 plaintext

            The server stores ciphertext only. A test reads the raw database file and fails if it finds one readable word.

          4. 04

            app access

            per folder

            Every AI app gets its own key and only the folders you allow. Revoke it and its next request fails.

          5. 05

            audit trail

            sealed hourly

            Every read is logged and folded into a Merkle root. Change one line and the proof breaks, in your own browser.

          6. 06

            attack surface

            0 server dependencies

            The server and the vault page use no npm packages and no third-party scripts, under a strict content security policy. Less code you have to trust.

          Not independently audited yet. The claims above are checked on every change by an end-to-end test suite that runs a real server, a real connector and the same crypto your browser uses.
