API reference

A small API,read only whereit matters

Public endpoints anyone can call, app endpoints an app key can call, and the session API the vault page uses. Apps can read what they were given and, when allowed, suggest sealed memories; they cannot change one. Everything an app endpoint returns is encrypted.

Basics

Every path is relative to the SYNOVAX server your vault lives on, for example https://synovax.tech. Requests and responses are JSON. An error is JSON too, { "error": "..." }, with an HTTP status that says what kind (below). A request body is at most 4 MB, except a folder key rotation, which may be 64 MB.

Terminal
curl https://synovax.tech/api/seals?limit=3
Public
No key, no session.
App
Authorization: Bearer a.<app id>.<token>. The token is HKDF-SHA256 of the app key's secret with the label vault/app/auth/v1, in base64url; the server keeps its SHA-256.
Vault
Authorization: Bearer s.<session token>, from signing in. Never a cookie.
Admin
Authorization: Bearer adm.<admin token>, from the admin password. Only the public token details.

Public endpoints

GET/api/statuspublic

Health of the server, the database, the seal job, the immune test and backups. Powers the status page.

Response
{
        "ok": true,
        "time": "2026-11-25T10:00:04.512Z",
        "startedAt": 1764057600000,
        "uptimeMs": 86400000,
        "database": { "state": "ok", "ms": 0.3 },
        "seals": {
          "job": "ok", "periodMs": 3600000, "nextCloseAt": 1764068400000,
          "open": 2, "overdue": 0, "lastRunAt": 1764064790000,
          "latest": { "seq": 41, "periodStart": 1764061200000, "periodEnd": 1764064800000,
                      "root": "…", "count": 7, "prev": "…", "chain": "…" },
          "total": 41, "published": false
        },
        "immune": { "enabled": true, "latest": { "hourStart": 1764064800000, "ranAt": 1764064801000, "total": 98, "held": 98 } },
        "backups": { "enabled": true, "intervalMs": 21600000, "lastAt": 1764050000000 },
        "counts": null,
        "statsMinVaults": 100
      }

job is ok, starting, behind (reads from a finished period not sealed yet), late or failed. open counts reads waiting for the running period; overdue counts unsealed reads of finished periods. counts stays null until the server holds statsMinVaults vaults.

GET/api/sealspublic

The newest seals, newest first. ?limit= 1 to 500 (50 by default). With ?from=<seq>, seals from that number on, oldest first, to walk the chain.

Response
{
        "seals": [{ "seq": 41, "periodStart": 1764061200000, "periodEnd": 1764064800000,
                    "root": "…", "count": 7, "prev": "…", "chain": "…" }],
        "periodMs": 3600000,
        "nextCloseAt": 1764068400000
      }
GET/api/seals/:seqpublic

One seal by its number, in the same shape. 404 when there is none.

GET/api/seals/:seq/proof?leaf=<hex>public

The Merkle proof for one leaf of a seal. A leaf is a salted hash and says nothing about the read behind it. 404 when the leaf is not part of that seal.

Response
{ "seal": { "seq": 41, "root": "…", … }, "leaf": "…", "leafIndex": 3,
        "proof": [{ "side": "R", "hash": "…" }, { "side": "L", "hash": "…" }] }
GET/api/immunepublic

The public test of the hidden-instruction checks: the attacks and disguises, the latest round with every result, and the recent rounds (?limit= 1 to 500, 48 by default). GET /api/immune/:hour gives one round by its start time in milliseconds.

Response
{
        "enabled": true, "periodMs": 3600000, "nextAt": 1764068400000,
        "strains": [{ "id": "override", "name": "Ignore previous instructions", "text": "…" }],
        "disguises": [{ "id": "plain", "name": "As written" }],
        "latest": { "hourStart": 1764064800000, "ranAt": 1764064801000, "total": 98, "held": 98,
                    "prev": "…", "hash": "…", "results": [{ "strain": "override", "disguise": "plain", "held": true }] },
        "recent": [{ "hourStart": 1764064800000, "ranAt": 1764064801000, "total": 98, "held": 98, "prev": "…", "hash": "…" }]
      }
GET/api/statspublic

Totals: { "vaults", "memories", "reads", "seals" }. Counts only.

GET/api/configpublic

What the vault page needs before signing in: { "appName", "sealPeriodMs", "iterations", "statsMinVaults", "connectorPath" }. connectorPath is set only on a server running on your own machine.

GET/api/token · /api/token/holderspublic

The public $SYNOVAX details the admin published, and the top 20 holders counted from Robinhood Chain ({ "available": false, "reason": "no-contract" } before a contract address is published; "stale": true when the last good list is served because the chain could not be reached).

Signing in

The browser derives everything from the passphrase or the 24 words; these routes only ever see the derived sign-in key, never what unlocks the vault.

POST/api/auth/saltpublic · 60 a minute

{ "username" } → { "salt", "iterations" }. Names that do not exist get a made-up but stable salt.

POST/api/auth/registerpublic · 10 an hour

{ "username", "salt", "iterations", "authKey", "recoveryAuthKey", "wrappedVaultKey", "wrappedVaultKeyRecovery", "boxPub", "boxPrivWrapped" } → { "token", "keys" }. 409 when the name is taken.

POST/api/auth/loginpublic

{ "username", "authKey", "totp"? } → { "token", "keys" }. 401 with "needTotp": true when a two-step code is needed.

POST/api/auth/recoverpublic

{ "username", "recoveryAuthKey" } → { "token", "twoFactorReset", "keys" }, the keys including the copy locked with the 24 words.

POST/api/auth/logoutvault

Ends this session.

App endpoints

What the connector calls. Each is written to the owner's read log before it answers.

GET/api/app/infoapp

The folders this app may read, with the folder keys wrapped for it, whether it may suggest, and the vault's inbox key with its tag. Logged as folders.

Response
{ "appId": "…", "canSuggest": true, "boxPub": "…", "vouch": "…",
        "folders": [{ "id": "…", "meta": "v1.…", "wrappedKey": "v1.…" }] }
GET/api/app/memoriesapp

The encrypted heads (title, tags, first 240 characters) of every memory in the granted folders, or in one with ?folderId=. Search happens on the caller's side. Logged as list, with the folder or *.

Response
{ "memories": [{ "id": "…", "folderId": "…", "head": "v1.…", "createdAt": 1764000000000, "updatedAt": 1764000000000 }] }
GET/api/app/memories/:idapp

One memory with its encrypted body. 404 for a memory outside the granted folders, without saying whether it exists. Logged as read.

POST/api/app/suggestapp · 30 an hour

{ "box": "box1.…" }, a suggestion sealed to the vault's inbox key → { "id" }. 403 unless the owner allowed suggestions; 429 over the hourly limit or with 500 waiting. Logged as suggest.

POST/api/app/caughtapp · 300 an hour

{ "ids": [ … ] }, 1 to 50 memory ids from which the connector removed hidden instructions → { "logged" }. Ids outside the granted folders are ignored. Each is logged as caught.

The vault session API

The vault page itself uses these. They take only ciphertext for anything you wrote, and a vault session. They are not meant for other programs, but nothing stops you: the whole router is one readable file, server/index.js.

RouteWhat it does
GET /api/vaultYour key bundle, folders and memories, as ciphertext.
PUT /api/folders/:idMake or rename a folder (encrypted name, wrapped key). At most 200.
POST /api/folders/:id/rotateA new folder key: every memory encrypted again, and the apps that keep access get the new key, in one step. 409 if the folder changed meanwhile.
DELETE /api/folders/:idDelete a folder and its memories.
PUT /api/memories/:idSave a memory (encrypted head and body). At most 20,000.
DELETE /api/memories/:idDelete a memory.
GET, PUT, PATCH, DELETE /api/apps…List, add, change the folders and suggestion switch of, or revoke an app. At most 50.
GET /api/inbox, DELETE /api/inbox/:idSuggestions waiting, as sealed boxes; remove one after you decide.
GET /api/log, GET /api/log/:id/proofYour read log with salts, and the proof of one entry.
GET /api/sessions, DELETE /api/sessions/:id, POST /api/sessions/sign-out-othersSigned-in devices.
GET /api/account, PUT /api/account/passphrase, DELETE /api/accountYour key bundle and switches; a new passphrase (signs out other sessions); delete everything (type your vault name to confirm).
POST /api/account/2fa/setup, enable, disableTwo-step sign-in.

Errors and limits

StatusMeaning
400The request is malformed. The message names the field.
401No session, an ended session, a wrong sign-in, or an app key that was revoked or never existed.
403The app may not do this: a folder it was not given, or suggestions while they are off.
404No such endpoint, or nothing there that you may see.
405A method other than GET or HEAD for a page.
409A name already taken, a folder that changed while its key was being replaced, or a newer save of the token details.
413The request is too large.
429Too many requests. Wait a little and try again.

Sign-in limits count failed attempts only: 10 a minute per name and address for a passphrase, 5 per 10 minutes for the 24 words, 200 failures an hour per vault (blocking only addresses that failed on it), and 20 sign-in requests a minute per address. Two-step changes: 10 per 10 minutes per vault. Admin sign-in: 5 failures per 15 minutes per address.
