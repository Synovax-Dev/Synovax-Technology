Verify

Check it yourself,by hand

Your vault checks a log entry against its seal with one button. This page is the long way round: the same checks with every step in the open, and code you can run without trusting ours.

Check one read

Three ways in. Every step of the walk is shown under the result, so you can compare the numbers with your own run of the script further down.

Nothing is sent anywhere: the page only does the arithmetic.

Check the whole seal chain

Fetches every seal from the first to the newest and checks that each one commits to the one before it. If your vault was opened in this browser before, it also checks that the newest seal your vault saw then is still in the history, unchanged.

What a seal is made of

Two hash rules and one entry format, the same in the browser, on the server and in the script below.

  • The salt is 16 random bytes per entry. Without it a leaf cannot be linked to a read.
  • Leaves, inner nodes and chain hashes start with different bytes (0x00, 0x01, 0x02), so one can never pass for another.
  • An unpaired node at the end of a level moves up unchanged.
Seal rules
data  = JSON.stringify([id, ts, vault_id, app_id, action, target, salt])
      leaf  = SHA-256( 0x00 ‖ data )
      node  = SHA-256( 0x01 ‖ left ‖ right )
      chain = SHA-256( 0x02 ‖ JSON.stringify(["seal/v1", seq, periodStart, periodEnd, root, count, prev]) )

With your own code

A complete check in plain Node.js, with no SYNOVAX code in it. Paste the entry from Copy entry into e and run it with node verify.mjs.

verify.mjs
import { createHash } from "node:crypto";

      const sha = (...parts) => createHash("sha256").update(Buffer.concat(parts)).digest();
      const site = "https://synovax.tech";

      // 1. The leaf, from the entry you copied out of your read log.
      const e = { id: "", ts: 0, vault_id: "", app_id: "", action: "read", target: "", salt: "", seal: 0 };
      const data = JSON.stringify([e.id, e.ts, e.vault_id, e.app_id ?? null, e.action, e.target ?? null, e.salt]);
      let node = sha(Buffer.from([0]), Buffer.from(data, "utf8"));
      const leaf = node.toString("hex");

      // 2. The proof and the published seal, from the public API.
      const { proof } = await (await fetch(`${site}/api/seals/${e.seal}/proof?leaf=${leaf}`)).json();
      const seal = await (await fetch(`${site}/api/seals/${e.seal}`)).json();

      // 3. Walk up.
      for (const { side, hash } of proof) {
        const sib = Buffer.from(hash, "hex");
        node = side === "R" ? sha(Buffer.from([1]), node, sib) : sha(Buffer.from([1]), sib, node);
      }
      console.log(node.toString("hex") === seal.root ? "verified" : "NOT verified");

What a passed check proves

It proves

Exactly this entry, with this app, this action, this target and this time, was part of the seal when it was made. Change one character and the leaf no longer leads to the root. With the chain, no earlier seal was changed or dropped since you last looked.

It does not prove

That nothing else happened. A seal cannot show that a server wrote every request down, and seals are kept by the server: a history rewritten before anyone kept a copy would not show. Both limits are in the threat model.
